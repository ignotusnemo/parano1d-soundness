## Preprocessing, matrix selection and activation

### Lemma 1. The metadata names one ordered bank

`decode_v21_runtime_metadata_pinned` requires the v2.1 magic, a bounded exact length and a complete canonical `RuntimeParts` decoding. The decoder requires the expected object version, four known configuration flags, three legal class configurations, valid witness slices and complete layouts. It consumes the entire input and checks canonical re-encoding.

`Bank::pin` hashes the configuration identity, complete public-IO specification, all three matrix digests and PCS shapes, each class's block verifier-key digest, the parent verifier-key digest and all three post-commit identities. The independently supplied bank pin is compared with that recomputed digest. Hence an accepted metadata substitution either preserves that entire ordered statement or produces a binding failure in the declared fixed-primitive interface.

`Bank::parse` then checks exact IO length, both lanes of the bank digest and both lanes of every matrix and post-commit digest. Class codes are exactly 0, 1 and 2. The base flag and each liveness flag are canonical booleans. A dead lane has zero point and value coordinates. The base flag is true exactly at activation height. Thus a proof cannot use a different class, matrix recipe or uninitialized lane under the same authenticated IO without violating a checked equation or the binding condition.

### Lemma 2. Loaded and embedded rows retain the pinned relation

For file-loaded matrices, `into_runtime` fixes each loader's class shape and matrix digest from the authenticated bank. `CompactFieldR1cs::open` authenticates the complete canonical artifact against those values. `Bank::authenticate` checks that same shape and statement digest at use.

For an embedded build, `embed_v21_pack` checks the executable schedule and activation for every class. It runs `preflight_build_matrix` on each exact compressed blob. The bank's three authenticated class identities are the identities decoded in the published native-profile replay. The current profiles are Small m23, Large m24 and Native m24, with their separately pinned matrix digests and source-derived PCS geometry.

### Lemma 3. The authorization boundary closes its predecessor

`AuthorizationOriginCertificate::verify` first checks the parent height, terminal height and semantic ID, predecessor class, epoch height, allowed predecessor-origin encoding and all transport lengths. Its claimed predecessor request must equal the verified predecessor origin's request. It then decodes the previous-bank terminal and calls `VerifiedOrigin::from_authorization_boundary`.

The previous bank's terminal verifier replays the selected proof and checks every required fresh or live accumulated matrix claim. A cache hit therefore replaces only a previously successful check of the identical carried obligation.

## Three-class transcript and source adapter

### Lemma 4. Exactly one predecessor is selected

Let s0,s1,s2 be the wires allocated by `parent_selector`. The relation enforces si^2=si, si*sj=0 for i!=j, sum(si)=1 and authenticated_class=s1+alpha*s2, where alpha is the distinct field encoding of class 2. Idempotence in a field gives si in {0,1}. Pairwise exclusion and the sum give exactly one selected wire. The class equation identifies that wire uniquely with the authenticated predecessor class.

For the base flag b, the three arm gates are gi=(1+b)*si. Boolean b=0 gives exactly one active predecessor. Boolean b=1 gives no active predecessor. Every selected verifier rejection equation E is imposed under gi*E=0. Hence each nonbase satisfying assignment retains every rejection equation of its selected arm.

The current authenticated compact flags are 7: fused boolean pins, reused linear rows and shared m24 replay. A fused gated row has w=g*(E+w), with checked boolean g. At g=0 it requires w=0 and permits E. At g=1 it requires E=0. Eliminating its fresh auxiliary w therefore gives exactly g*E=0. Reusing a free linear row solves a linear equation for a wire with a nonzero coefficient, multiplies by that coefficient's inverse and consumes the row once. This replaces its previous tautology with the same required linear equation. Both transformations preserve the selected rejection constraints. The native audit exercises these functions with all eight combinations of fused pins, linear-row reuse and symbolic product aliases. Shared-prefix selection is exercised separately in the recorder audit.

### Lemma 5. Every inactive obligation is preserved

For every point limb and value limb, `bind_lane` imposes

```text
out = previous + gi*(folded + previous).
live_out = live_previous + gi*(live_previous + 1).
```

When gi=0 these are exact equality with the predecessor lane, including all coordinates and liveness. When gi=1 they are the selected folded claim and liveness one. The base arm additionally pins every current lane to zero. Applying these equations independently to all three classes proves that a class change preserves every inactive outstanding obligation.

The assembly copies the complete bank and sealed-origin prefix from the same predecessor IO. Its selected parent semantic ID is pinned to the actual block parent. All ten start-accumulator lanes equal that predecessor's end lanes, or the verified origin lanes at the base boundary. The current end lanes equal the public current IO. These equalities connect the selected proof to the exact State transition and ancestry edge.

### Lemma 6. Shared m24 replay preserves the selected transcript

`replay_shared` requires equality of the Large and Native field shapes, complete PCS statement bytes and parent layouts. For z=s2, every selected expression is x0+z*(x0+x1). Since z is boolean, it equals the Large expression at zero and the Native expression at one. The shared root, deferred claims and recorder source wires use this same selection.

`select_prefix` additionally requires equal operation sequences, buffered/pending shapes, current absorb recipe, source/challenge counts, permutation count and C1 profile. It constrains z to a boolean and selects every data and challenge expression with the formula above. Its numerical state is the state of that same selected recorder. Thus continuing the shared recipe is pointwise the selected native recipe. Each class's fresh claim is still folded under its own gi, so sharing the suffix preserves Lemma 5.

`checked_pcs_binding_groups` merges entries only when their full tree descriptions and full leaf/path/root obligations are equal. Its selectors are boolean and mutually exclusive. Their sum is therefore the indicator of the identical obligation represented by that group. Gating once by that sum is equivalent to all of the original mutually exclusive gated equalities.

`pin_selected_recording_role` binds the selected child and predecessor recording roles separately. For three arms its source expression is cell+sum(si*(source_i+cell)). At the unique selected arm this reduces exactly to that arm's source expression. The selected recording binds the leaf lanes, path directions and both root limbs. The ordinary native/trace transcript recurrence, wide-challenge map and permutation arithmetic are the existing local channel argument. The mux and coalescing identities above extend that argument to the current three-class implementation.

Together Lemmas 4 through 6 establish the deterministic native/trace source adapter. The remaining adaptive compiler obligation is the one shared experiment that represents and extracts all required children. It is included in the all-root condition.

## Native acceptance and canonical State installation

### Lemma 7. Each remote terminal is checked against its exact context

The fixed node callback `verify_history_step_terminal` delegates to `HistoryProtocolRuntime::verify_terminal`. The runtime chooses the verifier from the authenticated candidate height. After activation it requires the configured finance runtime and decodes the three-class terminal under that bank. It resolves a verified origin, then calls that bank's complete terminal verifier with the exact candidate header and epoch.

The complete three-class terminal verifier checks the origin and public IO, verifies the local header boundary, replays the selected proof and authenticates every required fresh or live matrix claim. The returned accepted accumulator therefore belongs to that bank, header, epoch and origin, under the declared local soundness and binding conditions.

### Lemma 8. The four canonical admission routes preserve that authority

| Route | Authority before State installation | Binding and commit invariant |
|---|---|---|
| Ordinary inbound block | Full terminal callback on the uncommitted candidate | Native parent, PoW, epoch and resource checks precede materialization. Materialized root must equal the header before the block, terminal and State commit together. |
| Recursive suffix | Non-cloneable `VerifiedHistoryStepTerminal`, then a boundary-bound suffix capability | Every next body has the required height and previous hash. The final body equals the fully verified tip header. Each body's native checks and exact State root are checked. The capability advances only after a successful commit. |
| Reorg | Individually verified complete bundles or a verified recursive suffix bound to the current tip/finalized view | The complete replacement is linked, ends at the verified terminal and wins fork choice. | Snapshot | `VerifiedSnapshotBoundary` created after the full terminal callback | The boundary equals the staged exact header. The installer reopens and reauthenticates every sparse segment inside the transaction. Headers, State, terminal and tip commit together. Hot State changes only after success. |

The constructors of the terminal, suffix, reorg and snapshot authority types keep their fields private and provide no peer deserialization route. Every production callback at their construction sites is the fixed verifier callback above. Metadata parsing supplies an untrusted lookup key until that callback succeeds.

Before installing even the first live-suffix body, the fixed node validates the complete immutable header plan. `SyncPlan::suffix` recomputes every cached header hash and checks the first link to the base and every subsequent height/parent link. `apply_exact_suffix_offthread` decodes every fetched body, compares its complete header with that plan, checks exact body/source counts and checks that the final body ends at the selected target. It then verifies that final terminal and rechecks the current base under the writer lock. Thus the whole sequence is connected to the verified tip before any prefix is installed.

For a recursive suffix, induction on its next-height counter now proves the exact prefix invariant on that prevalidated immutable sequence. It begins at the authorized boundary. A successful step checks the next linked header and native State root, commits, then advances the capability. The final step also checks equality with the verified terminal header and stores the complete terminal. Hash binding and the coupled all-root ancestry condition relate every already-linked intermediate header to that final recursive statement, including an interrupted durable prefix.

For reorgs, the write-lock preflight rechecks the original tip and finalized checkpoint, ancestor, replacement chain, final verified header and fork-choice work. The common reorg transaction is reached only after every staged native step succeeds. Its rollback path reloads the old durable epoch. Thus a failed body or stale authorization preserves the accepted old branch.
